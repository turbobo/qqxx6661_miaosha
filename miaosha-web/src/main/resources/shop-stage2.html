柜台 A · 悲观锁SELECT FOR UPDATE

DB 行锁串行化：并发请求排队等锁，一个一个扣减，业务成功率 94%~100%。

柜台 B · Guava 令牌桶 + 乐观锁10 令牌/秒

1 秒内拿不到令牌直接拒绝——把突发削成均匀流量，CAS 冲突大幅下降。

两个武器：限流削峰 + 悲观锁兜底

-- 悲观锁：事务内锁行 SELECT * FROM stock WHERE id = ? FOR UPDATE; -- 其他事务在等锁 UPDATE stock SET sale = sale + 1 WHERE id = ?; -- 轮到我了再扣 -- 令牌桶：非阻塞 tryAcquire，拿不到令牌直接失败 guavaRateLimiter.tryAcquire(1, SECONDS)

悲观锁是「卖得完」的最稳策略（50~500 VUs 下 QPS 稳定 328~340），代价是高并发排队 RT 上升；令牌桶则从入口拦截 85% 的突发请求，让乐观锁的 CAS 冲突大幅降低。

对比实验：同样 ×20 连点——柜台 A 全部排队成功后逐个扣减；柜台 B 突发流量被令牌桶削峰，拿不到令牌的请求被直接拒绝。
