逐步演进路径

面试和简历描述时，可以按问题驱动讲清每一步为什么要升级。

1

同步下单

先完成票务查询、抢票、扣库存和订单创建的基础闭环。

2

数据库锁

使用悲观锁或乐观锁解决并发扣库存下的超卖问题。

3

MQ 削峰

接口快速提交，订单异步消费，降低开票瞬间数据库写压力。

4

Redis Lua 预扣

目标形态：Redis 原子预扣库存 + MQ 幂等落单 + 结果查询。

页面结论

当前代码适合展示演进思路；真正节假日高峰建议继续升级到目标 V3。

正确性优先

悲观锁和乐观锁都能解决数据库层超卖，但无法从根上降低数据库入口流量。

性能靠削峰

V2 异步链路把用户请求和订单创建解耦，是从同步抢票走向高并发抢票的关键一步。

最终形态

Redis Lua 原子预扣库存、MQ 幂等落单、Redis 结果查询和补偿对账，才适合节假日峰值流量。
