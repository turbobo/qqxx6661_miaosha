CAS 失败会返回「购买失败」，请求并未白跑——它证明了版本号确实拦住了并发冲突。

乐观锁：不加锁，用版本号做「提交前比对」

UPDATE stock SET sale = sale + 1, version = version + 1 WHERE id = ? AND version = ? -- 只有版本号没被改过才生效

请求进来先读 version=3，提交时发现别人已经改成 4 了，WHERE 匹配 0 行 → 本次更新失败。防住了超卖，但**冲突的请求全部失败**：高争用下 CAS 冲突率超 97%，业务成功率仅 1.1%~1.7%。

点「并发抢购 ×20」观察：20 个并发请求里，成功的往往只有 1 个，其余 19 个全部 CAS 冲突返回失败。
