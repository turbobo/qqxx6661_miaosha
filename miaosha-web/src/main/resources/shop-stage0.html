下单操作台

真实调用后端接口，每次点击都会真实扣减 MySQL 库存并创建订单。

这个方案为什么是反面教材？

① 查库存SELECT count-sale 读取剩余量，此时并发线程读到同一个值
② sale+1基于读到的旧值计算 sale=sale+1，再 UPDATE 写回
③ 插订单INSERT 订单记录，与扣减不在同一事务

高并发下线程 A、B 同时读到 sale=100，各自 +1 后都写回 sale=101：一次「丢失更新」。订单插了 2 条，库存只扣了 1 件——超卖与账实不符由此而来。

实测：50 VUs 压测下 HTTP 成功率 100%，但业务成功率仅 3.8%（15354 次请求只落库 583 单）。试试上面的「疯狂连点 ×20」，看订单数和库存扣减是否对得上。
